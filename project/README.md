# Основа проекта: Node.js/Express + React + PostgreSQL

## Что внутри

```
project/
├── docker-compose.yml     ← описывает все 3 сервиса
├── .env.example            ← пример переменных окружения (скопируй в .env)
├── backend/                ← Express API
│   ├── Dockerfile
│   └── src/
│       ├── server.js       ← точка входа сервера
│       ├── db.js           ← подключение к PostgreSQL
│       └── routes/
│           └── health.js   ← примеры роутов (/api/health, /api/db-check)
└── frontend/                ← React (Vite) + nginx
    ├── Dockerfile
    ├── nginx.conf           ← отдаёт статику и проксирует /api на backend
    └── src/
        ├── main.jsx
        └── App.jsx
```

Три контейнера в одной докер-сети:
- **postgres** — база данных, наружу порт не открыт (безопаснее)
- **backend** — Express API на порту 5000 (виден только внутри сети)
- **frontend** — React-сборка, отдаётся через nginx на порту **8888**

Всё общение фронта с бэком идёт через `/api/...` — nginx сам проксирует
эти запросы на контейнер backend, поэтому тебе не нужно думать про CORS
и адреса в браузере.

## Как развернуть через Portainer

1. Залей содержимое папки `project/` в git-репозиторий (это и есть корень репо).
2. В Portainer: **Stacks → Add stack**.
3. Выбери способ **Repository** и укажи свой git-репозиторий (или вставь
   содержимое `docker-compose.yml` вручную через **Web editor**, если пока
   не хочешь тащить git-интеграцию).
4. В разделе **Environment variables** стека добавь переменные из
   `.env.example` (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`) —
   обязательно поменяй пароль на свой.
5. Deploy the stack.
6. Через пару минут (первая сборка образов) открывай
   `http://<IP-сервера>:8888` — должна открыться страница с надписями
   "Backend: {...}" и "БД: {...}" — если оба говорят `"status":"ok"`,
   всё поднялось и база отвечает.

## Как дальше делать/менять страницы (фронтенд)

Это обычный React-проект на Vite:
- Компоненты — в `frontend/src/`. Сейчас есть только `App.jsx`.
- Чтобы добавить новую страницу — самый простой путь установить
  `react-router-dom` (`npm install react-router-dom` внутри `frontend/`)
  и завести папку `frontend/src/pages/` с файлами вида `Home.jsx`,
  `About.jsx` и т.д., а в `App.jsx` подключить роутинг.
- Локально можно разрабатывать без докера: `cd frontend && npm install &&
  npm run dev` — поднимется дев-сервер с горячей перезагрузкой (по
  умолчанию на порту 5173). Для реального обращения к API в деве добавь
  прокси в `vite.config.js` (`server.proxy['/api']`) на `http://localhost:5000`.
- Когда меняешь код и пушишь в git — Portainer можно настроить на
  пересборку стека по кнопке **Pull and redeploy** (или через webhook).

## Как дальше делать/менять API (бэкенд)

- Роуты лежат в `backend/src/routes/`. По примеру `health.js` создавай
  новые файлы (например `users.js`) и подключай их в `server.js` через
  `app.use('/api', require('./routes/users'))`.
- `backend/src/db.js` экспортирует готовый `pool` из библиотеки `pg` —
  просто импортируй его (`const pool = require('../db')`) и делай
  `pool.query('SELECT ...')`.
- Локально без докера: `cd backend && npm install && npm run start`
  (нужен локальный Postgres или проброшенный порт 5432 из контейнера).

## Как работать с базой данных (просто и понятно)

Сейчас база пустая — только служебная СУБД поднята, таблиц нет.

**Вариант 1 — миграции руками через SQL-файлы (самый простой для старта).**
Создай в `backend/` папку `migrations/` с файлами вида
`001_init.sql`, `002_add_users.sql` и т.д. Пока таблиц немного, можно
просто подключаться к базе и один раз прогонять эти файлы:

```bash
# зайти внутрь контейнера с базой
docker exec -it myapp_postgres psql -U appuser -d appdb

# или прогнать файл целиком из хоста
docker exec -i myapp_postgres psql -U appuser -d appdb < backend/migrations/001_init.sql
```

**Вариант 2 — когда таблиц станет больше, поставь ORM.**
Например `Prisma` (`npm install prisma @prisma/client` в backend) — она
сама генерирует и применяет миграции, и даёт удобный API вместо сырых
SQL-запросов. Это стоит сделать, как только появится 3-4 таблицы со
связями — руками их поддерживать станет неудобно.

**Для просмотра данных глазами**, пока порт 5432 закрыт наружу, проще
всего:
- временно раскомментировать `ports: ["5432:5432"]` у сервиса `postgres`
  в `docker-compose.yml` и подключиться любым GUI-клиентом (DBeaver,
  TablePlus, pgAdmin) к `<IP-сервера>:5432`;
- либо просто заходить командой `docker exec -it myapp_postgres psql -U appuser -d appdb`
  и смотреть таблицы через `\dt`, `SELECT * FROM ...`.

## Дальнейшие шаги (рекомендуемый порядок)

1. Задеплоить эту основу через Portainer, убедиться что `/api/health` и
   `/api/db-check` отвечают `"status":"ok"`.
2. Спроектировать первые таблицы (например `users`) и накатить через
   `migrations/001_init.sql`.
3. Добавить в backend реальные роуты (CRUD) под эти таблицы.
4. Добавить во frontend страницы, которые эти роуты используют.
5. Когда появится авторизация/сессии — можно вернуться и обсудить это
   отдельно, сейчас в основе её нет специально, чтобы не усложнять старт.
